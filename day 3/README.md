Спецификация ER-диаграммы для Варианта 3 (Библиотека)
Таблица	Атрибуты
Книги	id_книги INT PK AI, название VARCHAR(200) NN, год INT, isbn VARCHAR(20) UNIQUE, количество_экземпляров INT NN DEFAULT 1
Авторы	id_автора INT PK AI, имя VARCHAR(100) NN, фамилия VARCHAR(100) NN
Книги_Авторы	id_книги INT FK → Книги, id_автора INT FK → Авторы (составной PK)
Читатели	id_читателя INT PK AI, фамилия VARCHAR(50) NN, имя VARCHAR(50) NN, отчество VARCHAR(50), телефон VARCHAR(20), адрес VARCHAR(200), дата_регистрации DATE
Выдача_книг	id_выдачи INT PK AI, id_книги INT FK → Книги, id_читателя INT FK → Читатели, дата_выдачи DATE NN, дата_возврата_план DATE NN, дата_возврата_факт DATE, статус VARCHAR(20)
Штрафы	id_штрафа INT PK AI, id_читателя INT FK → Читатели, причина VARCHAR(200), сумма DECIMAL(8,2), оплачен BOOLEAN DEFAULT FALSE
Контрольные вопросы
1. Почему связь M:N требует дополнительной таблицы? Приведите пример из вашего варианта.

Ответ: Связь M:N (многие ко многим) требует промежуточной таблицы, так как реляционная модель не может напрямую хранить множественные связи. В моём варианте (Библиотека) это связь между Книгами и Авторами через таблицу Книги_Авторы, так как одна книга может иметь нескольких авторов, и один автор может написать несколько книг.

2. Какие атрибуты должны быть у промежуточной таблицы в вашем варианте?

Ответ: В промежуточной таблице Книги_Авторы должны быть:

id_книги - внешний ключ на таблицу Книги

id_автора - внешний ключ на таблицу Авторы

Составной первичный ключ из этих двух полей

3. Что означает ON DELETE RESTRICT и ON UPDATE CASCADE при создании внешнего ключа?

Ответ:

ON DELETE RESTRICT - запрещает удаление записи из родительской таблицы, если на неё есть ссылки в дочерней

ON UPDATE CASCADE - при обновлении значения в родительской таблице автоматически обновляет соответствующие значения в дочерней

4. Как в MySQL Workbench создать составной первичный ключ (из двух полей)?

Ответ: При создании таблицы в режиме редактирования выделить оба поля и нажать кнопку с ключом (Primary Key), либо на вкладке Foreign Key указать составной ключ.

5. Почему важно указать AUTO_INCREMENT для первичного ключа?

Ответ: AUTO_INCREMENT автоматически генерирует уникальные значения при вставке новых записей, что упрощает добавление данных и гарантирует уникальность идентификаторов.

6. Как экспортировать ER-диаграмму в PDF?

Ответ: File → Export → Export as PNG/SVG/PDF → выбрать PDF → указать имя файла и сохранить.

7. Что такое 3 нормальная форма? Ваша диаграмма ей удовлетворяет?

Ответ: 3НФ требует, чтобы все неключевые атрибуты зависели только от первичного ключа и не было транзитивных зависимостей. Моя диаграмма удовлетворяет 3НФ: например, в таблице Выдача_книг нет полей, зависящих от других неключевых полей.
