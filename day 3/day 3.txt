Контрольные вопросы:
1. Почему связь M:N требует дополнительной таблицы?
Потому что в реляционной БД внешний ключ может хранить только одно значение. Промежуточная таблица разбивает связь M:N на две связи 1:M.
Пример: читатели → выдача книг ← книги.
2. Какие атрибуты должны быть у промежуточной таблицы?
Два внешних ключа (ссылки на связываемые таблицы) + атрибуты связи (дата выдачи, дата возврата, статус).
3. Что означает ON DELETE RESTRICT и ON UPDATE CASCADE?
RESTRICT — запрещает удаление родительской записи, если есть дочерние.
CASCADE — при изменении ключа в родительской таблице автоматически обновляет его во всех дочерних.
4. Как в MySQL Workbench создать составной первичный ключ?
На вкладке Indexes выбрать PRIMARY, затем в секции Index Columns добавить нужные поля.
Или через SQL: PRIMARY KEY (поле1, поле2).
5. Почему важно указать AUTO_INCREMENT для первичного ключа?
Автоматически генерирует уникальный ID, упрощает вставку, исключает дубликаты.
6. Как экспортировать ER-диаграмму в PDF?
File → Export → Export as PNG/SVG, затем конвертировать в PDF. Или File → Print Diagram → Save as PDF.
7. Что такое 3 нормальная форма? Ваша диаграмма ей удовлетворяет?
3НФ — отсутствие транзитивных зависимостей (неключевые поля зависят только от первичного ключа).
Да, удовлетворяет. Поле статус — допустимая денормализация для удобства запросов.
